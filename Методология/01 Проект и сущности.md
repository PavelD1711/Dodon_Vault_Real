# 🎯 Что такое проект

**Проект** — ограниченное во времени усилие с измеримой целью и бюджетом (деньги/время/люди), у которого есть начало и конец.

В отличие от **процесса** — процесс идёт постоянно (например, «оперирование парком вагонов»), проект — до результата и закрывается.

## Признаки проекта

- Есть **цель** — конкретный результат, а не «улучшить» абстрактно
- Есть **срок** окончания
- Есть **владелец** — один ответственный
- Есть **бюджет** (деньги / часы / люди)
- Есть **критерий закрытия** — как поймём что готово

## Типы проектов

- **Внутренние** — для собственных компаний (Сайт Инкомтранс v2, HR-постановка)
- **Клиентские** — под конкретного клиента (246-К, Continental Bridge)

# 📦 Сущности проекта

Каждая сущность = отдельный тип заметки в vault со своим frontmatter.

## 1. 🎯 Цель (Goal)

_Финальный результат проекта. Одна цель = один проект._

```yaml
type: goal
project: "Сайт Инкомтранс v2"
description: "Запустить обновлённый сайт с фирстилем и SEO"
owner: "[[Павел]]"
start: 2026-09-01
due: 2026-11-30
status: active                   # planned | active | done | cancelled
success_criteria:                # как поймём что достигнута
  - "Сайт в проде на incomtrans.su"
  - "SEO ≥ 80/100"
  - "Трафик ≥ 500 уник/мес"
budget: 500000                   # опционально, в рублях
tags: [it, marketing]
```

## 2. 🔑 Ключевой результат (KR)

_Измеримая веха на пути к цели. Не «работа», а «состояние которое достигнуто»._

```yaml
type: kr
goal: "[[Цель Сайт Инкомтранс v2]]"
title: "Фирстиль утверждён"
due: 2026-09-15
status: todo                     # todo | in_progress | done | blocked | at_risk
progress: 0                      # 0..100
owner: "[[Павел]]"
depends_on: []                   # список других KR
weight: 20                       # % вклада в цель, опционально
```

## 3. ✅ Задача (Task)

_Работа под KR. Одна задача = одно действие с исполнителем и дедлайном._

```yaml
type: task
kr: "[[KR1 Фирстиль]]"
title: "Логотип v2 финальная версия"
assignee: "[[Дизайнер]]"
due: 2026-09-10
estimate: 8                      # часов
status: todo
```

## 4. 👤 Человек (Person)

_Все люди проекта: команда, клиенты, подрядчики, стейкхолдеры._

```yaml
type: person
role: "Дизайнер"
company: "Инкомтранс"
contacts:
  telegram: "@example"
  email: "..."
```

## 5. 📌 Событие (Event)

_Внешняя дата, которую нельзя двигать: встречи, съезды, дедлайны налоговой. Влияет на планирование._

```yaml
type: event
date: 2026-10-15
title: "Совет директоров"
related_kr: ["[[KR3 Дизайн]]"]
participants: ["[[Павел]]"]
kind: meeting                    # meeting | conference | deadline | external
```

## 6. ⚠️ Риск (Risk)

_То, что может пойти не так и повлиять на цель или KR._

```yaml
type: risk
title: "Дизайнер уйдёт в отпуск в октябре"
severity: medium                 # low | medium | high | critical
probability: high                # low | medium | high
impact: "Сдвиг KR3 на 2 недели"
mitigation: "Найти backup к 25.09"
related_kr: ["[[KR3 Дизайн]]"]
status: open                     # open | mitigated | realised | closed
```

## 7. 🔀 Гейт / Развилка (Gate) — обсуждается

_Точка принятия решения. Не результат, а выбор пути._

```yaml
type: gate
title: "Агентство или своими силами"
due: 2026-10-05
question: "Готовим сайт сами или отдаём агентству?"
criteria: "Бюджет ≥ 500к → агентство"
decision: null                   # заполняется когда решено
depends_on: ["[[KR1 Фирстиль]]", "[[KR2 Контент]]"]
```

## 8. 📅 Чекин / Ретроспектива (Checkin) — обсуждается

_Периодическая точка сверки: раз в неделю смотрим что случилось, что дальше._

```yaml
type: checkin
project: "[[Сайт Инкомтранс v2]]"
date: 2026-09-15
what_happened: "KR1 закрыт, KR2 на 60%"
what_next: "Фокус на KR2 + подготовка к развилке"
blockers: ["[[Риск: Дизайнер отпуск]]"]
```

# 🔗 Связи

```
                  ┌───────────────────┐
                  │      🎯 ЦЕЛЬ      │
                  └────────┬──────────┘
                           │ (goal)
              ┌────────────┼─────────────┐
              │            │             │
         ┌────▼───┐   ┌────▼───┐    ┌────▼───┐
         │ 🔑 KR1 │   │ 🔑 KR2 │    │ 🔑 KR3 │
         └───┬────┘   └───┬────┘    └────┬───┘
             │            │              │
        ┌────▼──────────────────┐        │
        │ ✅ Задачи (много)     │        │
        └───────────────────────┘        │
             │                            │
     assignees ──→  👤 Люди              │
             │                            │
     ⚠️ Риски ──────────────→ related_kr ┘
             │
     📌 События ────────────→ related_kr
             │
     🔀 Гейты ──────────────→ depends_on
             │
     📅 Чекины ──→ project
```

Связи идут в обе стороны через wikilinks. Открываешь любую сущность → в Backlinks видишь всё, что с ней связано, автоматически.

# ❓ Открытые вопросы

Обсудить с Павлом и зафиксировать:

1. **Один проект = одна цель или несколько?**
   Мой вариант: 1 проект = 1 главная цель. Если целей несколько — это программа (набор проектов).

2. **Гейты как отдельная сущность или разновидность KR?**
   KR = «результат» (готово), Gate = «решение» (выбор пути). Различие есть, но добавляет сложности.

3. **Задачи хранить в vault или в Todoist / Yougile?**
   Вариант: в Obsidian — только KR и стратегические задачи; мелкие todo — в Todoist. Или всё в Obsidian?

4. **Как обозначать процессы (не проекты)?**
   Оперирование парком — это не проект, а постоянный процесс. Отдельный тип `process`? Или пока не трогаем?

5. **Чекины / ретроспективы нужны отдельной сущностью?**
   Или обойдёмся дневником?

6. **Дополнительные сущности?**
   - Бюджет (расходы, платежи)
   - Документы / артефакты (Brand book, договор)
   - Клиент — отдельный тип или через `Люди`
