# 🎯 Что такое проект

**Проект** — ограниченное во времени усилие с измеримой локальной целью и бюджетом (деньги/время/люди), у которого есть начало и конец, и которое **влияет на одну или несколько стратегических целей** одной или нескольких дорожных карт.

В отличие от **процесса** — процесс идёт постоянно (например, «оперирование парком вагонов»), проект — до результата и закрывается.

## Признаки проекта

- Есть **локальная цель** — конкретный результат проекта
- Есть **срок** окончания
- Есть **владелец** — один ответственный
- Есть **бюджет** (деньги / часы / люди)
- Есть **критерий закрытия** — как поймём что готово
- Есть **влияние на стратегические цели** (одну или несколько, возможно из разных дорожных карт)

## Типы проектов

- **Внутренние** — для собственных компаний (Сайт Инкомтранс v2, HR-постановка)
- **Клиентские** — под конкретного клиента (246-К, Continental Bridge)

# 📐 Двухуровневая модель

Ключевая идея: работа Павла ведётся на **двух уровнях**.

## Уровень 1: Дорожные карты (стратегический)

- Одна **дорожная карта** = стратегия одного бизнеса / направления
- Пример: `Инкомтранс`, `Continental Bridge`, `Мессериаш`
- Внутри карты — **2-3 стратегические цели** (Strategic Goals, SG)

## Уровень 2: Проекты (операционный)

- Каждый **проект** имеет свою **локальную цель** и набор **KR**
- Проект **влияет на одну или несколько стратегических целей**, возможно из разных дорожных карт
- Проекты могут **влиять друг на друга** через cross-project зависимости

## Схема

```
🗺 ДОРОЖНАЯ КАРТА "Инкомтранс"          🗺 ДОРОЖНАЯ КАРТА "Continental Bridge"
├─ 🎯 SG1: Выручка 500М/год             ├─ 🎯 SG1: 3 клиента в Монголии
├─ 🎯 SG2: Доля рынка 12%               ├─ 🎯 SG2: Оборот CB 100М/год
├─ 🎯 SG3: Чистая прибыль 15%           └─ ...
└─ 🎯 SG4: ROE 25%
     ▲     ▲                                 ▲
     │     │                                 │
     └─────┼─────────────────────────────────┘
           │ strategic_impact
   ┌───────┴────────────┐
   │ 🚧 ПРОЕКТ           │
   │ "Найм финдира"      │
   │                     │
   │ local_goal:         │
   │  Финдир в компании  │
   │                     │
   │ KR1 KR2 KR3         │
   └─────────┬───────────┘
             │ blocks / feeds / enables
             ▼
   ┌────────────────────┐        ┌────────────────────┐
   │ Проект             │        │ Проект             │
   │ "Фин. автоматиз."  │        │ "Бюджет 2027"      │
   └────────────────────┘        └────────────────────┘
```

## Пример: критичный проект

**Проект «Найм финансового директора»** влияет на:
- 🎯 Инкомтранс → Чистая прибыль
- 🎯 Инкомтранс → ROE
- 🎯 Continental Bridge → блокирует финансовые проекты
- 🎯 Мессериаш → финансовая функция

→ Когда видно всю картину связей — сразу понятно, что этот проект критический.

# 📦 Сущности

## 1. 🗺 Дорожная карта (Roadmap)

_Контейнер стратегии одного бизнеса / направления. Внутри — стратегические цели и связанные проекты._

```yaml
type: roadmap
title: "Инкомтранс 2026-2027"
horizon: "2026-2027"
owner: "[[Павел]]"
strategic_goals:
  - "[[SG1 Выручка 500М к 2027]]"
  - "[[SG2 Доля рынка крытых 12%]]"
  - "[[SG3 Чистая прибыль 15%]]"
  - "[[SG4 ROE 25%]]"
projects:                          # автоматически видно через backlinks, но полезно явно
  - "[[Проект Сайт Инкомтранс v2]]"
  - "[[Проект Найм финдира]]"
  - "[[Проект HR-постановка]]"
status: active
```

## 2. 🎯 Стратегическая цель (Strategic Goal, SG)

_Метрика верхнего уровня. Не «сделать сайт», а «выручка 500М»._

```yaml
type: strategic_goal
roadmap: "[[Инкомтранс 2026-2027]]"
title: "Выручка 500М/год к концу 2027"
horizon: 2027-12-31
metric: "выручка, млн руб/год"
current_value: 320
target_value: 500
status: on_track                   # on_track | at_risk | off_track | achieved
```

## 3. 🚧 Проект (Project)

_Ограниченное во времени усилие с локальной целью и влиянием на стратегические цели._

```yaml
type: project
title: "Найм финансового директора"
owner: "[[Павел]]"
start: 2026-09-01
due: 2026-12-31
status: active                     # planned | active | done | paused | cancelled

# Влияние вверх (может быть несколько, из разных дорожных карт)
strategic_impact:
  - roadmap: "[[Инкомтранс 2026-2027]]"
    goals: ["[[SG3 Чистая прибыль]]", "[[SG4 ROE]]"]
  - roadmap: "[[Continental Bridge]]"
    goals: ["[[SG2 Оборот 100М]]"]

# Локальная цель проекта
local_goal: "Финансовый директор нанят, вышел, за 90 дней принял функцию"

# Cross-project связи
blocks:                            # эти проекты не поедут без результата этого
  - "[[Проект Финансовая автоматизация]]"
  - "[[Проект Бюджет 2027]]"
feeds:                             # результат этого = вход в эти
  - "[[Проект Reporting система]]"
depends_on: []                     # этот проект ждёт результата этих

# Бюджет
budget: 500000                     # опционально
team: ["[[HR-агентство]]", "[[Павел]]"]

tags: [hr, finance, critical]
```

## 4. 🔑 Ключевой результат (KR)

_Измеримая веха проекта. Не «работа», а «состояние достигнуто»._

```yaml
type: kr
project: "[[Проект Найм финдира]]"
title: "3 финалиста на встрече с Павлом"
due: 2026-10-15
status: todo                       # todo | in_progress | done | blocked | at_risk
progress: 0                        # 0..100
owner: "[[Павел]]"
depends_on: []                     # другие KR
weight: 30                         # % вклада в локальную цель, опционально
```

## 5. ✅ Задача (Task)

```yaml
type: task
kr: "[[KR1 3 финалиста]]"
title: "Прозвонить 5 HR-агентств"
assignee: "[[Павел]]"
due: 2026-09-10
estimate: 3                        # часов
status: todo
```

## 6. 👤 Человек (Person)

```yaml
type: person
role: "HR-агентство"
company: "..."
contacts:
  telegram: "@example"
```

## 7. 📌 Событие (Event)

```yaml
type: event
date: 2026-10-15
title: "Совет директоров"
related_kr: ["[[KR3 Дизайн]]"]
related_project: "[[Проект Сайт v2]]"
kind: meeting                      # meeting | conference | deadline | external
```

## 8. ⚠️ Риск (Risk)

```yaml
type: risk
title: "Финдир не найдётся до конца года"
severity: high                     # low | medium | high | critical
probability: medium
impact: "Сдвиг всей финансовой трансформации на 2027"
mitigation: "Параллельно рассматривать интерим-финдира"
related_project: "[[Проект Найм финдира]]"
related_sg: ["[[SG3 Чистая прибыль]]"]
status: open                       # open | mitigated | realised | closed
```

## 9. 🔀 Гейт (Gate)

_Точка принятия решения. Не результат, а выбор пути._

```yaml
type: gate
title: "Внешний CFO или интерим"
due: 2026-10-05
question: "Идём в постоянного финдира или берём интерим на 6 мес?"
criteria: "Если 2 сильных кандидата — постоянный, иначе — интерим"
decision: null                     # заполняется когда решено
project: "[[Проект Найм финдира]]"
depends_on: ["[[KR1 3 финалиста]]"]
```

## 10. 📅 Чекин (Checkin)

_Периодическая точка сверки._

```yaml
type: checkin
project: "[[Проект Найм финдира]]"
date: 2026-09-13
what_happened: "Пообщался с 3 агентствами, 1 подходит"
what_next: "Оффер этому агентству, старт поиска"
blockers: []
kr_updates:
  - kr: "[[KR1 3 финалиста]]"
    progress: 10
```

# 🔗 Типы cross-project связей

| Тип | Смысл | Пример |
|-----|-------|--------|
| **blocks** | «этот проект блокирует тот» | Найм финдира → блокирует Финансовая автоматизация |
| **feeds** | «результат этого = вход в тот» | Фирстиль → Сайт |
| **depends_on** | обратная к blocks (для удобства) | Финансовая автоматизация → depends_on Найм финдира |
| **enables** | не блокер, но ускоряет | CRM запущен → enables Активные продажи |

Направления связей вводятся в frontmatter проекта. Backlinks показывают обратные связи автоматически.

# 🔗 Полная схема связей

```
                  ┌─────────────────────────┐
                  │   🗺 ДОРОЖНАЯ КАРТА     │
                  └────────────┬────────────┘
                               │ contains
              ┌────────────────┴────────────────┐
              │            (2-3 SG)              │
         ┌────▼────┐   ┌────▼────┐    ┌────▼────┐
         │ 🎯 SG1  │   │ 🎯 SG2  │    │ 🎯 SG3  │
         └────▲────┘   └────▲────┘    └────▲────┘
              │             │              │
              │        strategic_impact    │
              │             │              │
              └─────────────┴──────────────┘
                            │ (from many projects)
                    ┌───────┴───────┐
                    │ 🚧 ПРОЕКТ     │
                    │  local_goal   │
                    └───┬───────┬───┘
                        │       │ blocks / feeds
                        │       ▼
                        │  ┌──────────┐
                        │  │Другой    │
                        │  │проект    │
                        │  └──────────┘
                   ┌────┼────┐
                   │    │    │
              ┌────▼─┐ ┌▼───┐┌▼────┐
              │🔑KR1 │ │🔑KR2││🔑KR3│
              └───┬──┘ └──┬─┘└──┬──┘
                  │       │      │
             ┌────▼──────────────┐
             │ ✅ Задачи (много) │
             └───────────────────┘
                    │
     assignees ──→  👤 Люди
     ⚠️ Риски ──────────→ related_project, related_sg
     📌 События ──────────→ related_project, related_kr
     🔀 Гейты ──────────→ project, depends_on
     📅 Чекины ──────────→ project
```

Все связи через wikilinks в обе стороны. Открываешь любую сущность → Backlinks показывают всё связанное автоматически.

# ❓ Открытые вопросы (осталось 5)

### ~~1. Один проект = одна цель или несколько?~~ ✅ РЕШЕНО (2026-09-06)

- Проект имеет **одну локальную цель** + **влияние на 1+ стратегических целей** (возможно из разных дорожных карт)
- Дорожная карта имеет **2-3 стратегических цели**
- Дорожных карт может быть много

### 2. Гейты как отдельная сущность или разновидность KR?

KR = «результат готов», Gate = «решение о выборе пути».
Мой вариант: **оставить отдельно**, но использовать только когда реально нужен выбор.

### 3. Задачи хранить в vault или в Todoist / Yougile?

Мой вариант: в Obsidian — KR и стратегические задачи; мелкие todo — в Todoist. Через wikilink на Todoist-задачу если нужно.

### 4. Как обозначать процессы (не проекты)?

Оперирование парком — постоянный процесс, не проект. Нужен отдельный тип `process`? Или пока не трогаем?

### 5. Чекины / ретроспективы нужны отдельной сущностью?

Или обойдёмся дневником? Мой вариант: **отдельная сущность**, потому что позволяет строить историю проекта.

### 6. Дополнительные сущности?

- Бюджет (расходы, платежи)?
- Документы / артефакты (Brand book, договор)?
- Клиент — отдельный тип или через `Люди`?
