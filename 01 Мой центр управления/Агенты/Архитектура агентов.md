# Архитектура агентов — Мой центр управления

## Иерархия

```
Time Assistant (диспетчер времени)
  └── Администратор контекста (1 агент = 1 контекст)
        └── Администратор дорожной карты (1 агент = 1 ДК)
              └── Администратор проекта (1 агент = 1 проект)
```

---

## Уровни

### 🕐 Time Assistant / Pablo
**Роль:** Администратор контекста «Центр управления» + Диспетчер времени над всеми контекстами
**Контекст ЦУ включает:** идеологический контур (миссия, ценности, принципы), стратегическое планирование (год, спринты), ресурс времени (бюджет по 11 контекстам)
**Чат:** Time Assistant (`-5521808848`)
**Что делает:**
- Ведёт общий бюджет времени по 11 контекстам
- Видит факт из Toggl, сравнивает с нормативом
- Ставит бюджетные цели администраторам контекстов
- Принимает отчёты, корректирует нормативы
- Опирается на идеологический контур (ценности, принципы)

---

### 🗂 Администратор контекста
**Роль:** Управляет одним контекстом жизни целиком
**Уровень:** 1 агент = 1 контекст (ОБ, CB, Портфель и т.д.)
**Что делает:**
- Принимает бюджетную цель от Time Assistant
- Держит картину контекста: цели, дорожные карты, проекты
- Анализирует где тратится время Павла внутри контекста
- Предлагает что делегировать / автоматизировать / исключить
- Отчитывается Time Assistant (факт времени + прогресс КР)

---

### 🗺 Администратор дорожной карты
**Роль:** Погружён в одну дорожную карту внутри контекста
**Уровень:** 1 агент = 1 ДК (один контекст может иметь несколько ДК)
**Что делает:**
- Следит за вехами и ключевыми результатами ДК
- Управляет зависимостями между проектами
- Сигнализирует о рисках и отклонениях
- Отчитывается администратору контекста

---

### 📋 Администратор проекта
**Роль:** Ведёт конкретный проект
**Уровень:** 1 агент = 1 проект
**Что делает:**
- Следит за задачами, сроками, атрибутами проекта
- Контролирует качество заполнения (все поля, КР, риски)
- Обновляет статус
- Отчитывается администратору дорожной карты

---

## Принцип совмещения ролей

На начальном этапе **один агент может совмещать все три роли** внутри одного чата (контекст + ДК + проект). Разделять на отдельные чаты имеет смысл когда:
- Дорожных карт в контексте 3+
- Проектов в ДК 5+
- Нагрузка на агента становится избыточной
