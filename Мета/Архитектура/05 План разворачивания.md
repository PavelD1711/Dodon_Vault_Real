# План разворачивания

Пошаговое движение от Уровня 1 к Уровню 3.

## Этап A: Определение архитектуры команды *(1 сессия, 30-60 мин с Павлом)*

**Не начинать плодить агентов. Сначала — портрет команды.**

- [ ] Утвердить или переработать список ролей из [[03 Портрет команды агентов]]
- [ ] Для каждого агента прописать: роль / объект / функции / границы / личность / метрики
- [ ] Расставить приоритеты запуска
- [ ] Записать в vault: `Мета/Агенты/<Имя>/README.md` для каждого

## Этап B: Технический анализ и подготовка *(я делаю сам, 1-2 часа)*

- [ ] Проверить схему конфига OpenClaw про multi-agent
- [ ] Изучить, как добавить второго агента (документация + исходники)
- [ ] Оценить стоимость (токены/месяц) при 3-5 агентах
- [ ] Подготовить конкретный план изменений в `~/.openclaw/openclaw.json`
- [ ] Отчёт Павлу

## Этап C: Пилот на 2-3 агентах *(1-2 недели)*

Взять пилотных агентов (например: **Time Assistant + Финдир** + один бизнес-эксперт) и:

- [ ] Прописать в конфиге OpenClaw
- [ ] Дать каждому свой system prompt (детально)
- [ ] Настроить каналы (Telegram-группы)
- [ ] Проверить работоспособность каждого по отдельности
- [ ] Проверить `sessions_send` — переписку между агентами
- [ ] Проверить шеринг vault (у каждого свои зоны записи)
- [ ] Проверить проактивность (Time Assistant делает еженедельный отчёт через cron)
- [ ] Собрать feedback от Павла — что работает, что нет

## Этап D: Масштабирование *(2-3 недели после успешного пилота)*

- [ ] Разворачивание остальных агентов по приоритетам
- [ ] Оркестратор (если решаем идти в Уровень 3)
- [ ] Правила проактивности для каждого
- [ ] Дашборд наблюдаемости
- [ ] Регламент «прежде чем что-то делать — спроси нужного агента»
- [ ] Итеративная доводка

## Критерии перехода между этапами

**A → B:** есть утверждённый портрет команды (минимум 5 агентов расписаны)

**B → C:** есть план изменений в конфиге, оценка стоимости, «зелёный свет» от Павла

**C → D:** пилотные агенты работают >2 недель без критических сбоев, Павел доволен
