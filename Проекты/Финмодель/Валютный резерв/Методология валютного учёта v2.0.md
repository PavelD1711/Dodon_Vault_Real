# Методология валютного учёта — v2.0

> **Регламент управления валютным резервом группы (три ЮЛ).**
> Утверждено Павлом 08.09.2026 в результате разбора концепции v1.0 и итеративной работы через WIP-документ.

---

## 1. Назначение и границы

### Что покрывает эта методология

Методология описывает **управление единой валютной позицией группы** через три ЮЛ:

- ООО «Инком Транс» — Оператор вагонов
- ООО «Северный Путь» — Экспедитор
- ООО «Транзит»

Она регламентирует:

- Как **учитывается** валютный резерв (композиция обязательств и остатков)
- Кто и **как задаёт курс** дня
- Как **согласовываются акты** с клиентами и как в них попадает курс
- Как **финансовый отдел** принимает решение о конвертации
- Как **разделяется ответственность** между коммерческим блоком и финотделом
- Как **обрабатываются отклонения** — недовыполнение акта, уточнение расходов, изменение объёма
- Как результат отражается в **P&L** и в **управленческом балансе**

### Что НЕ покрывает

- Рублёвые операции (аренда парка, зарплаты, ₽-выручка от ₽-клиентов) — они живут в отдельной управленческой отчётности
- Бухгалтерский (регламентированный) учёт — методология описывает **управленческий** контур
- Внутренние ₽-переводы между ЮЛ группы

**Важно:** система оперирует **только $-потоками**. Рублёвая часть в валютную позицию не заводится.

## 2. Термины

| Термин | Определение |
|---|---|
| **Акт** | Произвольный документ, подписанный с клиентом, фиксирующий: станцию отправления/назначения, количество вагонов, ставку ($/вагон), **зафиксированный курс**. Синоним «Заявка». В методологии используется только «Акт». |
| **Курс акта** | Курс, по которому финотдел выдал сегодняшнюю цифру. Зашивается в подписанный акт. Юридически с клиентом закреплён и **не пересматривается**. |
| **Курс конвертации** | Реальный курс, по которому финотдел совершил операцию в банке (продажа/покупка $). Может отличаться от курса акта. |
| **Балансовый курс** | Стабильный управленческий курс для оценки $-остатков и обязательств в рублёвом эквиваленте в управленческом балансе. Меняется вручную, редко (годы). В операционных расчётах **не участвует**. |
| **Резерв (композиция)** | Совокупная валютная позиция группы: остатки $ на счетах + все ДЗ и КЗ в $. См. раздел 4. |
| **Целевой резерв** | Плановое значение композиции резерва группы (пример: $300 000). Задаётся руководством. |
| **Коридор резерва** | ±5 % от целевого значения. Пример: цель $300 000 → коридор $285 000…$315 000. Внутри коридора операций не проводим. |
| **Позиция** | Разница между целевым резервом и текущей композицией. Основа рекомендации на конвертацию. |
| **Действующая ДЗ / КЗ** | Обязательство, возникшее по факту оказания услуги (после оформления вагона / накладной с датой отправления). |
| **Будущая ДЗ / КЗ** | Обязательство, возникшее по факту подписания акта, но услуга ещё оказывается. |

## 3. Роли и разделение труда

### 3.1. Финансовый отдел — **владелец процесса**

Финотдел отвечает за:

- Поддержание резерва в целевом коридоре ±5 %
- Ведение и контроль **единой таблицы** (реестр актов + реестр конвертаций + реестр расходов)
- Выдачу курса **по запросу** менеджера/тарифника
- Принятие решения об исполнении рекомендации к конвертации (исполнить сегодня / отложить)
- Проведение физической операции в банке
- Отражение курсовой разницы в P&L «Финансовая деятельность»
- Установку и пересмотр **балансового курса**

### 3.2. Менеджер по продажам

- Запрашивает курс у финотдела **перед согласованием акта** с клиентом
- Считает клиенту ставку в $ по этому курсу
- Подписывает акт с зафиксированным курсом
- Вносит акт в таблицу: доход $, ставка $/вагон, количество вагонов, стороны

### 3.3. Специалист по тарифам

- По подписанному акту вносит в таблицу **расходы в $** (тарифы третьих сторон — КТЖ, УТИ и т.п.)
- Уточняет расходы если приходят фактические цифры отличные от плановых → пересчёт композиции

## 4. Резерв как композиция

### 4.1. Формула резерва

```
Резерв группы (композиция, $) =
    Остатки $ на счетах группы
  + Действующая дебиторская задолженность $
  + Будущая дебиторская задолженность $
  − Действующая кредиторская задолженность $
  − Будущая кредиторская задолженность $
```

**Разграничение «действующая / будущая»:**

- **Будущая** — акт подписан, курс зафиксирован, услуга **ещё идёт** (не закрыта актом закрытия)
- **Действующая** — услуга **закрыта актом закрытия**, обязательство перешло в реальное

**Важно:** будущие обязательства попадают в композицию **сразу при подписании акта** — не «когда придут деньги», а «когда возникло обязательство».

### 4.2. Целевой резерв и коридор

- **Целевой резерв** задаётся руководством (пример: $300 000)
- **Коридор**: ±5 % от цели. Для $300 000 → $285 000…$315 000
- Внутри коридора — **никаких операций** (не покупаем, не продаём)
- За пределами коридора → рекомендация к конвертации на **возврат к целевому центру** (не к границе коридора)

### 4.3. Резерв — общий на группу

- Резерв $300k — **единая цифра группы**, не распределяется по ЮЛ
- Физическое расположение $ на счетах — произвольное; финотдел сам решает где держать
- **Между российскими ЮЛ валюта не ходит** — только рубли. Внутригрупповые $-переводы не существуют как явление
- Позиция и рекомендация считаются **сводно** по группе

### 4.4. Что НЕ входит в резерв

- Рублёвые остатки, рублёвая ДЗ/КЗ
- $-эквивалент рублёвых обязательств (например, аренда парка в ₽, переведённая в $) — в v1.0 такое было, в v2.0 **исключено**

## 5. Курс дня — правила работы

### 5.1. Кто и как выдаёт

- Курс выдаёт **финансовый отдел**
- Выдаётся **по запросу**, не по расписанию
- Действует **до 16:00** текущего рабочего дня
- **После 16:00** — если нужна операция, менеджер снова запрашивает курс, финотдел выдаёт новый
- Финотдел **обязан** выдать курс по запросу без нареканий (это часть его роли как владельца процесса)

### 5.2. Где применяется

Один и тот же курс дня применяется **и там, и там**:

- Менеджер использует для расчёта ставки в акте с клиентом
- Финотдел использует как ориентир для своей конвертации

### 5.3. Курс конвертации vs курс акта

Если финотдел реально совершил операцию в банке по **другому** курсу — это **курс конвертации**, отдельная сущность. Разница между ним и курсом акта = **курсовая разница финотдела** (см. раздел 7).

### 5.4. Только рабочие дни

- Акты **не согласовываются** в выходные и праздники
- Курс не запрашивается вне рабочих банковских дней
- Сценарий «акт в субботу — какой курс?» не возникает

## 6. Жизненный цикл акта

Акт последовательно проходит **5 состояний** с точки зрения валютной композиции:

| # | Событие | Что меняется в композиции | Триггер |
|---|---|---|---|
| 1 | **Подписание акта** | +Будущая ДЗ $, −Будущая КЗ $ | Менеджер вносит акт в таблицу |
| 2 | **Оформление вагона** (накладная + дата отправления) | Будущая ДЗ → **Действующая ДЗ** | Факт оформления |
| 3 | **Поступление валюты от клиента** | Действующая ДЗ → **+Остатки $** | Выписка со счёта |
| 4 | **Оплата контрагенту** | Действующая КЗ → **−Остатки $** | Факт платежа |
| 5 | **Акт закрыт на 100 %** | Акт убирается из открытых обязательств | Обе стороны рассчитались |

### 6.1. Статусы акта в таблице

- ⚪ **Белый / серый** — открыт, в процессе (обычное состояние)
- 🟢 **Зелёный** — выполнен 100 %, деньги получены, акт закрыт
- 🟡 **Жёлтый** — выполнен частично (пример: 6/10 вагонов), нужен пересчёт
- 🔴 **Красный** — сорван / выполнен очень плохо, требует решения

### 6.2. Правило перерасчёта при неполном выполнении

- Акт **должен быть выполнен на 100 %**
- Если нет — акт подсвечивается + запускается процедура пересчёта (раздел 8.1)
- **Курсовые последствия недовыполнения относятся на менеджера**, подписавшего акт

## 7. Курсовые разницы — два слоя ответственности

Ключевой принцип v2.0: **курсовые разницы разделены по зонам ответственности**. Два блока не смешиваются.

### 7.1. Слой 1 — Коммерческий (P&L операционный)

- Курс акта → используется в **операционном P&L сделки** (доходы, расходы, маржа)
- **Зона ответственности:** коммерческий блок (менеджеры)
- Менеджер отвечает за маржу при том курсе, который ему дал финотдел

### 7.2. Слой 2 — Финансовый (P&L финансовой деятельности)

- Курс конвертации ≠ курс акта → разница = финансовый результат
- Формула: `(курс_конвертации − курс_акта) × объём $`
- **Зона ответственности:** финотдел
- Идёт в P&L **«Финансовая деятельность»**, не в операционный P&L сделки

### 7.3. Пример разделения

- Финотдел выдал курс 85,5. Менеджер подписал акт на $50 000 чистой позиции.
- P&L сделки считается по 85,5 → маржа 1 025 000 ₽ (для примера).
- Финотдел продал $50 000 по 85,3 (не угадал).
- Финансовый убыток: `(85,3 − 85,5) × 50 000 = −10 000 ₽` → в «Финансовую деятельность».
- **Операционный P&L сделки не меняется** — коммерсант получает свою маржу полностью.

### 7.4. Балансовый курс НЕ участвует в расчёте курсовых разниц

В v1.0 балансовый курс использовался в формуле «реализованной курсовой разницы» — это была ошибка модели. В v2.0 балансовый курс работает **только для управленческого баланса** (см. раздел 10).

## 8. Отклонения и пересчёты

### 8.1. Недовыполнение акта — алгоритм

Если акт выполнен частично:

1. **Определить невыполненную часть** в $:
   `Выпавший доход − Выпавший расход = Чистая выпавшая позиция`
2. **Найти конвертацию**, которая была проведена под эту позицию, и её курс
3. **Обратная операция** по текущему курсу банка:
   - Тогда продавали → теперь **докупаем** тот же объём
   - Тогда покупали → теперь **продаём** тот же объём
4. **Сравнить курсы** (курс тогда vs курс сейчас):
   - Курс в нашу пользу → на выпавшей позиции **заработали**
   - Курс против нас → **потеряли**
5. **Результат идёт в P&L менеджера** (ответственность за невыполнение — на нём)

**Пример:**
- Акт: 10 вагонов, доход $90k, расход $35k → чистая +$55k продано по 85,5
- Выполнено 6/10 → факт +$33k, выпало $22k
- Докупаем $22k по текущему 85,8
- Результат: `(85,5 − 85,8) × 22 000 = −6 600 ₽` → расход менеджера
- Если бы курс упал до 85,2: `(85,5 − 85,2) × 22 000 = +6 600 ₽` → доход менеджера

### 8.2. Уточнение расходов после подписания

- Пришёл фактический расход отличный от планового → пересчитывается ставка (в будущем — урок для менеджера)
- Композиция пересчитывается автоматически
- Финотдел получает **новую рекомендацию** к конвертации
- Разница между старой и новой продажей = курсовая разница финотдела (слой 2)

### 8.3. Полный срыв акта

- Обратная операция на всю чистую позицию акта
- Курсовые последствия → менеджеру
- Отдельно клиенту выставляется штраф по договору (это уже юридический контур, вне валютной системы)

## 9. Формула рекомендации к конвертации

### 9.1. Позиция

```
Позиция = Целевой резерв − Текущая композиция резерва
```

### 9.2. Правило рекомендации

| Условие | Действие |
|---|---|
| Композиция **внутри коридора** (цель ±5 %) | **Ничего не делаем** |
| Композиция **выше** верхней границы коридора | **Продать** валюту на возврат к центру |
| Композиция **ниже** нижней границы коридора | **Докупить** валюту на возврат к центру |

### 9.3. Округление

- Рекомендация округляется **до целого доллара** (центы отбрасываются)
- Пример: отклонение $55 123,47 → рекомендация «$55 123»

### 9.4. Комиссии банка

- Банковские комиссии при конвертации (0,1–0,3 %) **в модели не учитываются**
- Причина: несущественны на фоне оборотов группы; усложняют модель без практической пользы
- Комиссия физически уходит в общие расходы финансовой деятельности, но в **валютную позицию не заводится**

### 9.5. Пересчёт — event-based

Каждое событие пользователя → **немедленный пересчёт** позиции и обновление рекомендации. Не в конце дня, не батчами.

События-триггеры:
- Менеджер добавил акт
- Тарифник добавил/уточнил расход
- Финотдел провёл конвертацию
- Пришёл платёж от клиента / ушёл платёж контрагенту

## 10. Балансовый курс — только для управленческого баланса

### 10.1. Назначение

В момент сбора **управленческой отчётности** валютная композиция (резерв, $-ДЗ, $-КЗ, $-остатки) переводится в рубли **по балансовому курсу** для попадания в управленческий баланс.

### 10.2. Свойства

- **Стабилен** — от квартала к кварталу, от года к году
- Может держаться неизменным год, два, три
- Меняется **осознанно вручную**, при серьёзном основании (например, структурный сдвиг рынка)
- Устанавливает и пересматривает **финансовый отдел** (совместно с руководством)

### 10.3. Где применяется / не применяется

| Где | Применяется? |
|---|:---:|
| Управленческий баланс — оценка $-остатков, ДЗ, КЗ в рублях | ✅ Да |
| Расчёт композиции резерва (раздел 4) | ❌ Нет |
| Формула рекомендации к конвертации (раздел 9) | ❌ Нет |
| Курсовые разницы в P&L (раздел 7) | ❌ Нет |

## 11. Отчётность

### 11.1. P&L — куда что попадает

| Строка | Слой | Формула |
|---|---|---|
| Выручка / расход сделки | Операционный (коммерческий) | по курсу акта |
| Маржа сделки | Операционный | доходы − расходы |
| **Курсовая разница финотдела** | **Финансовая деятельность** | `(курс_конв − курс_акта) × объём $` |
| Курсовые последствия недовыполнения акта | P&L менеджера | по алгоритму 8.1 |
| Банковские комиссии | Финансовая деятельность | как есть |

### 11.2. Управленческий баланс

- $-остатки на счетах, $-ДЗ, $-КЗ переоцениваются **по балансовому курсу**
- Балансовый курс отражается как параметр системы с датой последнего пересмотра

### 11.3. Реестр валютных операций

Ведётся финотделом как отдельная сущность:
- Все конвертации (дата, направление, объём $, курс банка)
- Привязка к висящей позиции (какие акты закрывались)
- Курсовая разница по каждой операции

## 12. Табличный инструмент (SoP реализации)

**Реализация:** Google Sheets + автоматика.

Ключевые таблицы:

1. **Реестр актов** — все подписанные акты + статусы + связи с расходами
2. **Реестр расходов** — расходы по актам (фактические + плановые)
3. **Реестр конвертаций** — все операции финотдела с валютой
4. **Композиция резерва** — сводная позиция группы (пересчёт event-based)
5. **Рекомендация** — вычисляемая цифра к продаже/покупке
6. **Управленческий баланс** — переоценка по балансовому курсу

**Роли доступа:**
- Менеджеры → пишут в реестр актов
- Тарифники → пишут в реестр расходов
- Финотдел → пишет в реестр конвертаций, управляет балансовым курсом, читает всё
- Руководство → читает всё
