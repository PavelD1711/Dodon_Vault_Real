# Платёжный календарь + ДДС-план

## Зачем

Заменить ручные Excel-файлы финотдела. Дать живую картину: когда придут деньги, когда нужно платить — по дням, по ЮЛ, в $ и ₽.

Текущие инструменты (не нравятся):
- `План_Октябрь_2026.xlsx` — ручной план, пересобирается каждый месяц
- `Ежедневный_отчет_ФО.xlsx` — движение ДС + ДЗ/КЗ из 1С постфактум

## Юрлица

2 ЮЛ: **Северный путь** + **Транзит**
Инкомтранс — не входит.
Валюты: $ и ₽ в обоих ЮЛ одновременно.

## Модель данных (v0.2 — трёхуровневая)

```
Заявка (1) → Вагоны (N) → Платежи (M)
```

### Уровень 1 — Заявки
Лист `Заявки`. Павел думает заявками, не вагонами.

| Поле | Описание |
|------|----------|
| № заявки | Уникальный ID (авто) |
| Клиент | Из справочника Контрагенты |
| Маршрут | Ст. отправления → Ст. назначения |
| Груз | Наименование |
| Кол-во вагонов | План |
| Оператор | Экспедитор/владелец вагонов |
| Ставка клиент $ | За вагон |
| Ставка клиент ₽ | За вагон (если рублёвая) |
| Расход $ план | За вагон |
| Отсрочка клиент (дн) | +N дней от даты отправления |
| Предоплата поставщик (дн) | −N дней от даты отправления |
| Окно отгрузки | Дата начала — Дата конца |
| Статус | Активна / Закрыта / Отменена |
| ЮЛ | СП / Транзит |
| Комментарий | — |

### Уровень 2 — Вагоны
Лист `Вагоны`. Разворот заявки в конкретные вагоны.

| Поле | Описание |
|------|----------|
| № заявки | Ссылка на Заявки (VLOOKUP подтягивает клиента, маршрут, ставки) |
| № вагона | Факт. номер |
| Дата отправления факт | Якорь для расчёта платежей |
| Ставка клиент факт $ | Если отличается от плана в заявке |
| Расход факт $ | Если отличается от плана |
| Статус | В пути / Доставлен / Ожидание |

**Как раскладывать заявку в вагоны:** ⏳ ждём ответа Павла
- **(а)** Полуавтомат: указал кол-во → скрипт создаёт N пустых строк
- **(б)** Вручную: добавляешь по одному, VLOOKUP тянет из заявки ← рекомендация агента

### Уровень 3 — Платежи
Лист `Платежи`. Авторазворот каждого вагона в 4 движения денег:

| Тип | Формула даты | Сумма |
|-----|-------------|-------|
| Приход от клиента | Дата отпр. + Отсрочка клиент | Ставка клиент |
| Предоплата поставщику | Дата отпр. − Предоплата поставщик | Расход план |
| (резерв) доп. платёж 1 | — | — |
| (резерв) доп. платёж 2 | — | — |

## Ключевые особенности модели (голосовое 05.10)

- Клиент платит в $ или ₽; платежи идут частично на СП, частично на Транзит
- Расходы (РЖД, экспедиторы) несёт СП → возникает «выпадающая выручка на СП»
- Якорь всех платёжных дат = **дата оформления вагона**
  - Клиент: дата + N дней (отсрочка)
  - Поставщик: дата − N дней (предоплата) или дата + N дней (постоплата)
- Условия оплаты хранятся в **справочниках** (не в заявке вручную)
- Стартовая точка: остатки на **01.10.2026** + все активные заявки → картина БДР + БДДС
