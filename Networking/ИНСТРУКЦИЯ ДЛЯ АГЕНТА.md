- **Дашборды:** `Networking/00 Дашборды.md` (Dataview + Dataviewjs)

## 🔀 Три режима работы

Определяй режим по формату сообщения Павла:

### Режим 1 — «Массовый ввод ФИО»

Признак: **список фамилий+имён** в столбик или через переводы строк (10+ штук).

**Что делать:**
1. Для каждой строки распарси: `Фамилия Имя` или `Фамилия Имя Отчество`
2. Создай **заготовку** в `Networking/Фамилия Имя.md` (без отчества в имени файла)
3. Отчество попадает в поле `отчество` frontmatter
4. Если больше 20+ строк — используй **Python-скрипт** (образец в `/tmp/networking_batch.py` или в этом файле ниже)
5. **Проверь дубли** до создания (сравнение по имени файла)
6. **Проверь однофамильцев** после создания — предупреди Павла (не связывай проактивно, просто сообщи)
7. Коммит + push в vault с описанием пачки
8. Верни короткий отчёт: сколько создано / сколько дублей / список новых

**Template карточки-заготовки** — см. [ниже](#template-заготовки).

### Режим 2 — «Интервью по одному человеку»

Признак: Павел говорит «задавай вопросы по [ФИО]» или расширенно диктует про конкретного человека.

**Что делать:**
1. Открой файл `Networking/Фамилия Имя.md`
2. Посмотри что уже заполнено, что нет
3. **Задавай вопросы по одному полю за раз** (не заваливай списком)
4. Приоритет полей (спрашивай в этом порядке):
   1. **Компания + должность** — базовый идентификатор
   2. **Как познакомились** (дата, обстоятельства, через кого)
   3. **Статус отношений** (`знакомы` / `активно` / `близко` / `друзья` / `не_знаком_лично`)
   4. **Роли** (партнёр / клиент / поставщик / эксперт / инвестор / юрист / банкир / чиновник / сотрудник / коллега / ментор / знакомый / друг / бывший_сотрудник / предприниматель)
   5. **Экспертиза** — в чём силён
   6. **Контакты** — Telegram / телефон / email
   7. **Что даёт мне / Что я могу дать**
   8. **Связи** — кого знает из моей базы, кто его знает
   9. **Личное** — семья, ДР, интересы (по желанию)
5. **После каждого ответа Павла** — обнови файл + `дата_обновления` + коммит
6. Не додумывай, не заполняй за него, не расширяй. Только то, что сказал.
7. Когда карточка «достаточно заполнена» — предложи двигаться дальше

### Режим 3 — «Вопрос про граф связей»

Признак: Павел спрашивает «есть ли выход на X?», «через кого могу выйти на Y?», «кто мои super-connectors?», «кто в моей сети из [компания]?»

**Что делать:**
1. Читай папку `Networking/` (можно через `dir_list` + выборочный `read`)
2. Строй граф в памяти:
   - Узел = человек (файл)
   - Рёбра — из frontmatter: `знаком_через`, `знает_людей`, `связанные_люди`
   - Веса рёбер — из `качество_связей` (сильная/средняя/слабая)
3. BFS (обход в ширину) до цели
4. **Возвращай список маршрутов**, отсортированный по:
   - Длина пути (короче = лучше)
   - Качество связей (сильная > средняя > слабая)
   - Уровень доверия к промежуточному человеку (`уровень_доверия`)
5. Формат ответа:
   ```
   Найдено N маршрутов до [[Целевой Человек]]:
   
   Маршрут 1 (длина 2, сильные связи):
     Ты → [[Мост]] (доверие 5, активно) → Целевой
     Комментарий: ...
   
   Маршрут 2 (длина 2, средние связи):
     ...
   ```
6. Если не нашёл маршрутов — честно скажи «в текущем графе выхода нет».

## 📋 Правила именования

- **Формат файла:** `Фамилия Имя.md` (сортировка по фамилии в Obsidian, лучше для делового каталога)
- **Кириллица** — ОК
- **Отчество** — только в frontmatter (`отчество: Иванович`), НЕ в имени файла
- **Дубликаты** (два человека с одинаковым `Фамилия Имя`) — добавь компанию в скобках: `Иван Петров (Северный Путь).md`
- **Не переименовывай** файл после того как на него появились ссылки — либо через Obsidian rename (авто-обновляет ссылки), либо ручным поиском во всех файлах

## 🕸️ Граф связей — детали для поиска маршрутов

### Поля-рёбра в frontmatter

| Поле | Направление | Смысл |
|---|---|---|
| `знаком_через` | «мосты ко мне» — через кого я знаю этого человека (список) | Заполнять если статус = `не_знаком_лично` или знакомство было через посредника |
| `знает_людей` | «мосты от него» — кого из моей базы знает этот человек (список) | **Ключевое поле для поиска маршрутов «к кому он может дать интро»** |
| `связанные_люди` | общие связи по проекту/семье (список) | Двусторонняя, без явного направления |
| `качество_связей` | вес рёбер (map: `[[Имя]]: сильная/средняя/слабая`) | Опционально, для приоритизации маршрутов |

### Формулы приоритизации маршрутов

Оценка маршрута — композитная:
1. **Длина** пути (главный критерий, меньше = лучше)
2. **Минимальное качество звена** на пути (`сильная` > `средняя` > `слабая`)
3. **Минимальный уровень доверия** к промежуточным (шкала 1-5)

### Как формировать ответ на вопрос «есть ли выход на X»

- Если найден **прямой** контакт (Павел его знает лично) → сказать это первым
- Если найдены **2nd-degree** маршруты → показать все, сортированные
- Если найдены **3rd+ degree** — показать топ-3 самых сильных
- Если нет маршрутов — «в текущем графе выхода нет, попробуй...» (предложи ближайших по домену)
